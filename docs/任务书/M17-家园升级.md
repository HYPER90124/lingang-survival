# M17 任务书 — 家园升级（模型：sonnet）

## 开工前必读
PLAN.md（M3/M9/M11 交接备注 + v1.2 拍板备注）、docs/Schema.md、js/data/locations.js 的 home 定义与 actions 形状、js/engine/time.js 的 dayRollover。

## 目标
home 从「免费旅馆」变成可投资的据点：四项升级消耗中后期过剩物资，换取被动收益（候选池第二批 L）。

## 设计
升级状态存 `world.homeUpg:{door,rain,garden,storage}`（布尔，migrate 补空对象）。home 新增「修缮」行动打开升级浮层（或四个独立 action，实现从简），显示材料需求与效果，材料齐才可点：

| 升级 | 材料（参考，可自调） | 效果 |
|---|---|---|
| 加固门窗 door | scrapmetal×3 + tape×2 + toolkit 在包（不耗） | 尸潮夜 home 的 horde_safe_1 换安心变体（理智 -0 改 +2）；在家睡眠精力恢复 +10% |
| 雨水收集器 rain | glassbottle×3 + rope×1 + wire×1 | 雨天跨日结算自动 +2 rainwater 进储物柜（无储物柜则进背包，超重照规则处理） |
| 小菜园 garden | wildveggie×2（种子）+ rainwater×2 | 每 2 天 +1 wildveggie（跨日结算，存最近收获日 world.gardenDay） |
| 储物柜 storage | scrapmetal×2 + rope×2 + toolkit 在包 | 家中寄存：state 新增 `homeStorage:[]`，存取界面进 home 行动；寄存物不计负重 |

- dayRollover 挂 rain/garden 的被动产出（读 world.homeUpg，纯追加逻辑）。
- 储物柜 UI：仿背包面板做存/取双列表，容量上限 60 重量（防无限囤积，常量进 TUNE）。
- 每项升级完成配一段短文案（动手过程 1–2 段，照文风规范）；升级后 home 的 descDay/descNight 加一句可见变化（text 函数按 flag 分支）。

## 约束
- 材料需求要用「中后期才过剩」的材料（废铁/胶带/绳/瓶），别用食水硬通货；总成本对照 M9 平衡基线——四项全修好 ≈ 中期玩家 5–8 个游戏日的搜刮盈余。
- 被动产出别破坏「必须出门」：菜园+收集器合计供给不得覆盖单人食水需求的一半（对照 TUNE.thirstPer10/hungerPer10 算清楚写进交接备注）。
- homeStorage 走 SAVE_VERSION 迁移；与 M16 的存档槽改动如有先后，migrate 链要串起来测。
