# M4 任务书 — NPC 框架与好感度系统（模型：opus）

## 开工前必读
PLAN.md、docs/Schema.md、docs/NPC设定.md、M1–M3 交接备注。

## 目标
实现 NPC 系统层，让剧情模块只需注册纯数据。产出 `js/data/npcs.js`（NPC 静态数据 + 系统逻辑）。

## 产出
1. **NPC 注册表**：10 名 NPC 的静态数据——名字、专色、简介（好感面板用，随阶段揭露更多）、作息表（时段 → 地点，灰猫特殊处理为事件驱动）、初始 met/affinity。
2. **作息与在场判定**：`G.engine.npcAt(locationId)` 返回当前时刻在场 NPC；地点界面据此显示「找 XX 搭话」入口。
3. **好感度系统**：
   - 阶段换算（五阶阈值见 NPC设定.md）；好感变动到阈值不自动升阶，升阶由 stage fx 在剧情内完成（保证阶段剧情必看）；好感达标但阶段未升时，搭话入口显示提示态。
   - 日常搭话：每 NPC 每日一次通用互动（+1~2 好感，短文本池按阶段分层，每层 3 条起，文本遵守文风规范，此处文本量小由本模块自写）。
   - 送礼：每 NPC 登记喜好道具 2 种 / 厌恶 1 种（对照人设），送礼好感 ±，每日一次。
4. **剧情入口调度**：搭话时按 stage + storyFlags 查找当前可触发的 story 事件并优先于日常互动；无可用剧情时落回日常搭话。
5. **好感面板**（与 M2 的 UI 约定配合，如需新面板在 G.ui 下新增并登记）：已认识 NPC 列表、好感条、阶段名、当前提示（「他似乎有话想说」/「好感不足」）、已解锁剧情回顾标记。
6. **NPC 死亡/离场预留**：alive=false 时全部入口关闭，作息不显示；本期不写死亡剧情，仅留机制。

## 约束
- 不写阶段剧情正文（那是 M5–M7 的活），只写日常搭话与送礼短文本。
- storyFlags 锁序机制必须实测：跳序注册的事件不触发，已完成的不重复。

## 验收
控制台调好感走完 0→100：日常搭话文本随阶段变化、送礼生效、阶段卡在剧情事件前不自动升、作息时间表准确（对照 NPC设定.md 逐一核对）。
