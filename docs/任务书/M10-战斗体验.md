# M10 任务书 — 战斗体验重做（模型：opus）

## 开工前必读
PLAN.md（重点：M9 交接备注的数值平衡与测试方法、本任务书对应的 v1.1 规划备注）、docs/Schema.md「战斗」节、js/engine/combat.js 全文、js/data/enemies.js 全文。剧情文件只查涉及 `fx.combat` 的段落，不通读。

## 目标
战斗信息透明（每个选项显示成功率与后果）、遇敌前文本与敌人数量一致、主角战斗能力增强以平衡难度。

## 工作项

### 1. 战斗选项显示成功率与后果
- combat.js 新增 `G.engine.combatOptionInfo()`，按当前战斗状态返回各动作的实时数据：
  - **攻击**：命中率（`hitNormal` 0.9）+ 当前武器伤害区间（读 weaponInfo）。
  - **重击**：命中率（`hitHeavy`）+ 伤害区间×`heavyMult` + 精力消耗（`heavyEnergy`）。
  - **防御**：受伤 ×`defendReduce`（减伤 60%）。
  - **逃跑**：用 `tryFlee` 同一公式实时算（`fleeBase + (energy-50)/100 - 最快敌 speed×0.1`，超重 -0.4，钳制 0.05–0.95）——公式抽成共用函数，防止两处漂移。
  - **道具**：列出可用道具的 fx 摘要。
- render.js 战斗界面把这些数据渲染到按钮上，例：`攻击（90%·4-7伤）`、`重击（70%·10-16伤·-10精力）`、`逃跑（55%）`。移动端按钮宽度有限，格式自定但信息必须全。
- 战斗界面顶部显示敌方全员构成与各自余血（现在只有 log 文本，敌人数量不直观）。

### 2. 遇敌前文本与敌人数量一致
- 全库扫描 `fx.combat`（grep `combat:`，locations.js 12 处 + worldevents.js 约 13 处 + 各剧情文件约 18 处），逐条对照 `G.data.encounters` 编组人数与文本描述。
- 已确认的错例（务必修）：
  - locations.js `enc_market_1_p`：文本「一只跛行者」→ 实际 `zombie_pair`（跛行者×2）。
  - locations.js `enc_hospital_1_p`：文本「一具……坐了起来」→ 实际 `zombie_trio`（3 只）。
- 模糊表述（如 enc_metro_1_p「分不清有几个」）算合格；明确数量错误的必须改文本（不改编组，编组是平衡基准）。
- **系统级保险**：遇敌选项按钮后缀敌方构成，如「上前解决（跛行者×2）」——render.js 渲染 choice 时若 `fx.combat` 存在，解析编组自动拼接。这样以后新剧情写错文本也不至于误导玩家。

### 3. 主角战斗能力增强（平衡难度）
- **落地三个技能位**（M5/M7 已发放但引擎不读，M9 遗留）：
  - `skill:melee`（老秦线）：近战命中 +0.05 且伤害 +2（或等效，自测定）。
  - `skill:bandage`（林晚线）：绷带/急救类道具 fx 效果 ×1.5。
  - `skill:modding`（阿豆线）：武器耐久损耗减半（wearWeapon 每两次攻击 -1）。
- **基础手感调整**（改 `COMBAT_TUNE`，幅度自测定，方向如下）：
  - `hitHeavy` 0.62 → 0.70 左右（重击现在期望值低于普攻，没人用）。
  - 防御回合小幅回精力（+3~5），给「防御→重击」循环留操作空间。
  - 可选：连续命中给小幅增伤（连击奖励），提升爽感。
- **验收标准**：复刻 M9 的胜任机器人测试（30 天生存 5/5 保持），另加战斗专项：徒手 vs zombie_pair 胜率应明显高于修改前但不碾压；铁管 vs zombie_trio 应打得过但掉血肉疼；metro_horde/thug_squad 对无准备玩家仍构成真实威胁。前期紧张感不能丢。

### 4. 顺手修（M3 遗留）
- combat.js `playerAttack` 命中文案对人类敌人（thug_grunt/thug_brute）误套 `[zed]` 标签——按敌人 id 或新增 `human:true` 字段区分。

## 约束
- 数值只改 `COMBAT_TUNE` 集中常量；新增接口纯新增，不改既有接口签名。
- 改剧情文本只改数量表述，不动情节与文风（对照 docs/文风与内容规范.md）。
- 存档结构不变（战斗态本就不入档）。
