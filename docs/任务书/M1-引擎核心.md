# M1 任务书 — 引擎核心（模型：opus）

## 开工前必读
PLAN.md、docs/Schema.md、docs/世界观.md 的「时间与日历」节。

## 目标
实现游戏引擎层，不含 UI 渲染和游戏内容数据，产出 `js/engine/` 全部文件与 `index.html` 骨架。

## 产出
1. `index.html`：按 Schema 约定的引入顺序搭好骨架，body 内留 `#app` 容器。
2. `js/engine/state.js`：GameState 的创建（含新开局默认值）、读写工具（statAdd 钳制 0–100、flag 读写、绝对分钟换算）、条件 DSL 求值器 `G.engine.checkCond(cond)`、效果 DSL 执行器 `G.engine.applyFx(fx)`。
3. `js/engine/time.js`：时间推进 `advance(minutes)`（逐 10 分钟步进，处理跨日）、日期换算（第 0 天 = 7月14日周一，真实历法跨月跨年）、时段判定、每步进钩子（饥渴精力自然消耗挂此处，消耗速率常量集中放开头便于 M9 调平衡）、阈值效果检测（阈值清单见 Schema「阈值效果」）、睡眠结算 `sleep(hours)`。
4. `js/engine/events.js`：事件注册表 `G.data.events.register`、passage 注册表 `G.data.story.register`、触发检查 `checkEvents(trigger)`（四种时机见 Schema）、priority/once/cooldown 处理、scheduled 事件按 weekday 调度、日历 appointments 到期触发、stage 推进校验（只允许 +1）。
5. `js/engine/combat.js`：按 Schema 战斗节实现回合循环、五种玩家行动、武器耐久、感染判定、descPool 文本拼接、战斗结果回调（胜利掉落/逃跑/死亡）。
6. `js/engine/save.js`：3 槽位 + 自动档的 localStorage 存读、版本号迁移预留、导出/导入 Base64 存档码、死亡处理（弹读档界面）。
7. `js/engine/main.js`：启动流程（有档载入/无档进开局创建）、全局错误兜底。

## 约束
- 引擎不出现任何具体游戏内容（地点名、NPC 名、事件文本），全部通过 G.data 注册表取。
- UI 交互通过 `G.ui.*` 的约定接口调用（`G.ui.showPassage(id)`、`G.ui.refresh()`、`G.ui.showCombat(state)`、`G.ui.showLocation()`），M1 里先写成空函数占位并在文件头注释接口签名，M2 实现。
- 每个文件头部用注释块写明对外接口清单。

## 验收
- 用浏览器控制台注册一个测试事件 + 测试 passage，能完整走通：条件判定 → 触发 → 选项 fx 结算 → 时间推进 → 存档读档。
- 时间换算抽查：第 90 天 = 10月12日周日；跨年正确。
