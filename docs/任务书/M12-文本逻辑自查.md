# M12 任务书 — 全库文本逻辑自查（模型：fable）

## 开工前必读
PLAN.md（M5–M9 交接备注的 flag 清单 + v1.1 规划备注）、docs/文风与内容规范.md 自洽规则节、docs/NPC设定.md 关系网。剧情文件按排查项定点读，不通读。

## 背景
用户实测反馈：**第一次进入某地点/初见某人时，对话却说「这几次」**——首次/重复口径错乱。全库 grep「这几次」无字面命中，说明是同义表述或动态段落拼出来的，需要人工排查而非纯 grep。

## 目标
消灭「文本声称的历史与玩家实际经历不符」的全部场景。

## 排查项（按项逐一过，每项在交接备注登记结论）

1. **首次/重复口径**（用户实锤项，最高优先级）：
   - grep 嫌疑短语：`这几次|这几天|又来|还是你|老样子|照旧|每次|上次|总是|惯例` 等，逐条核对该段落的触发条件（once? cond 锁了前置 flag? 冷却可重复?）——可重复段落若用了「首次向」表述，或首次段落用了「熟客向」表述，都算 bug。
   - 重点嫌疑区：npcs.js 的日常搭话分层文本（每阶段 3 条随机，阶段 0 警惕期的条目不该有熟络口吻）；locations.js 的 36 条通用氛围事件（如 `amb_bar_1_p` 苏曼递水——初见还没搭过话就「没多说什么」递水，口径要核）；minor.js 老蔡「今天又来一个」（该句本身合理——他是疯的——但同类句式要逐个判断）。
   - 修法参考：给段落 text 函数按 `met`/阶段/flag 分支两版文案；或给事件加 `cond:{met:...}` 锁。改动最小者优先。
2. **敌人数量口径**：M10 已修战斗遇敌文本，本模块复核 M10 之后新改动 + 非战斗文本里提到敌情数量的地方。
3. **时段矛盾**：文本写「夜里/天亮/正午」的段落，核对事件触发时段限制是否真锁了对应时间（重点：worldevents.js 的尸潮/雨天链、各 rare_ 事件）。
4. **未发生事件引述**：NPC 台词提到其他 NPC 或事件的地方（关系网 6 条 + 暗线 3 条已在 M9 抽查过，本次全查）——引述内容若依赖某 flag 的剧情，核对是否加了对应 cond 或用了「氛围级模糊表述」（M7 交接注明的 su_gossip 类豁免仍有效）。
5. **性别双分支完整性**：grep 所有按 `gender` 分支的 text 函数，确认两分支都有内容、无一方漏写或复制粘贴串味（成人段落重点查）。
6. **道具/地点名称口径**：文本提到的道具名与 items.js 实名一致（如把「矿泉水」写成「纯净水」这类漂移）；M11 新增的水源文本一并纳入。
7. **驱动验证**：跑一遍首访机器人——新档依次首访 15 地点 + 首遇 10 NPC，dump 所有渲染文本，人工通读一遍首访文案（这是抓「这几次」类 bug 唯一可靠的网）。

## 约束
- 只改文案与 cond/分支，不动数值、不动事件结构与 flag 命名（存档兼容）。
- 改文案遵守 docs/文风与内容规范.md；成人内容段落改口径不改尺度。
- 每处修改在交接备注登记「段落 id + 问题 + 修法」，形成回归清单。

## 完成后
勾选 PLAN.md M12，交接备注附完整修改清单与「排查过但判定合理」的豁免清单（防止后人重复排查）。
