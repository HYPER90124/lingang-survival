# M9 任务书 — 整合测试、平衡与部署（模型：opus）

## 开工前必读
PLAN.md 全部交接备注、docs/Schema.md；其余文档按排查需要查阅。

## 目标
全游戏可玩、数值合理、部署上线。

## 工作项
1. **整合测试**：新开局连玩 30 游戏日的完整流程（两种性别各一轮）：三条主线推满、四条次线推满、全地点搜刮、战斗胜败逃、死亡读档、导出导入存档、日历各类标记；控制台零报错。
2. **自洽排查**：抽查跨线引用（关系网 6 条、暗线 3 条）文案是否与 flag 状态矛盾；抽查时段文案与实际时间匹配。
3. **数值平衡**：调 time.js 消耗速率、搜刮掉率、物价、战斗伤害、好感增速，目标——前期紧张（前 5 游戏日为食水奔波）、中期舒展（有余力推剧情）、无躺赢死循环（食物获取速率长期略紧）；毒瘾/感染系统实际构成威胁但可恢复。
4. **性能与兼容**：手机浏览器实测（至少 Chrome/Safari 各一），首屏加载、长文本渲染、localStorage 容量（存档预计 <200KB，留余量）。
5. **打包脚本**：`tools/build.js`（Node），内联全部 js/css 产出单文件 `dist/game.html`，剔除 _demo.js，验证 file:// 直开可玩。
6. **部署 GitHub Pages**：git 仓库整理、建远程仓库、启用 Pages（纯静态，记得加 .nojekyll），手机访问验证。托管风险已向用户说明，被下架时退路是单文件 + itch.io。
7. **收尾**：PLAN.md 标记 v1.0 完成，写后续扩展建议（新 NPC/新地点按现有 Schema 直接加数据文件即可）。

## 约束
- 平衡调整优先改集中常量，避免翻改散落数值；改动记录在交接备注。
- 修 bug 时保持 Schema 兼容，涉及存档结构变化走 save.js 版本迁移。
