# M14 任务书 — 服装与外观系统（模型：opus）

## 开工前必读
PLAN.md（重点：M2/M3/M9 交接备注 + v1.1 规划/拍板备注）、docs/Schema.md（道具与存档节）、js/engine/state.js（player 结构）、js/engine/save.js（migrate 版本迁移）、js/data/items.js 头部形状。

## 目标
DoL 式服装系统的临港版：三个服装槽 + 三属性，影响战斗、NPC 反应与事件分支；为 M15 入冬的保暖机制打地基。

## 设计（可在此框架内自行细化，超出框架先记交接备注）
- **槽位**：上装 / 下装 / 鞋，共 3 槽（DoL 的多层内外衣简化掉，别照搬）。
- **属性**：每件 `warmth`（保暖，M15 消费）/ `armor`（减伤，战斗时敌方伤害先扣 armor 总和的固定比例或点数，幅度自测）/ `decency`(体面，影响部分 NPC 事件与商店态度分支)。
- **耐久**：战斗每次被命中概率损衣（撕坏→属性减半→报废）；针线包道具可修。
- **初始装**：开局按性别发一套基础装（worn 系列），数值垫底。
- **数据**：items.js 新增 `type:'clothing'`，字段 `slot/warmth/armor/decency/durMax`；新增 12–18 件（搜刮/商店/剧情奖励各有来源，商城 mall 的户外柜、赵铁货架是天然上架点）。
- **引擎**：state.player 新增 `outfit:{top,bottom,shoes}`；equip/unequip 接口仿 equipWeapon；**存档结构变化必须走 save.js `migrate()`（G.SAVE_VERSION 递增 + normalize 补字段），老档读入给默认初始装**。
- **UI**：身体面板加服装区块（三槽显示+点击换装）；背包里 clothing 类可装备。
- **文本适配**：只做「决定性场景」的分支（成人场景的宽衣描写按是否着装分支、decency 过低时 3–5 个 NPC 给一句反应台词），不全库重写——工作量红线。

## 约束
- 存档迁移是本模块最大风险点，migrate 前后各跑一遍 M9 的求生机器人 + 满进度档导入验证。
- 数值别喧宾夺主：armor 总和的减伤不得超过防御动作的价值，否则战斗策略退化成堆装备。
- decency 只做氛围分支不做硬门槛（不锁剧情）。
